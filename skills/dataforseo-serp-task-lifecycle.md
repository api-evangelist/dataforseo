# DataForSEO — SERP task lifecycle

Base URL `https://api.dataforseo.com`. Free rehearsal host: `https://sandbox.dataforseo.com`
(same paths, same credentials, dummy data — use it while you are building).

## Auth

HTTP Basic on every request:

```
Authorization: Basic base64(login:password)
```

Credentials come from https://app.dataforseo.com/api-access. The API password is
generated by DataForSEO and is **not** the account password. Credentials cannot go in
the URL. There is no token exchange.

## The one rule that breaks most integrations

DataForSEO returns **HTTP 200 for nearly everything**. Only 401, 402, 404 and 500 ever
appear at the HTTP layer. The real outcome is the numeric `status_code` field, which is
present twice — once at the top level of the response and once inside every element of
`tasks[]`. **Check both.** A top-level 20000 with a task-level 40501 is a failed task
inside a successful request.

## Step 1 — Post the task

`POST /v3/serp/google/organic/task_post` (operationId **GoogleOrganicTaskPost**)

The body is a JSON **array** of task objects — up to 100 per request (101+ returns
`40006`). Generate and record your own task `id` before sending, or read the one
DataForSEO returns; you will need it to recover from a failed POST.

Useful body fields: `keyword`, `location_code`, `language_code`, `device`, `os`,
`depth`, `priority`, `tag` (your own correlation label), and the callback fields
`postback_url` / `pingback_url` / `postback_data`.

Expect `status_code` **20100** ("task created") per task.

## Step 2 — Find out it is ready

Two options. Prefer the webhook.

**Webhook (no polling).** Set `pingback_url` (notification only, supports `$id` and
`$tag` placeholders) or `postback_url` (the full result is POSTed to you; pair it with
`postback_data` to choose `regular` / `advanced` / `html`). Nothing is signed — treat the
callback as a trigger and re-fetch over authenticated HTTPS rather than trusting the body.
Missed callbacks are replayed with `POST /v3/appendix/webhook_resend` (operationId
**WebhookResend**, up to 100 ids, not double-charged).

**Polling.** `GET /v3/serp/google/organic/tasks_ready` (operationId
**GoogleOrganicTasksReady**) lists completed tasks you have not collected yet. Codes
`40601` (handed) and `40602` (in queue) mean not ready — back off and poll again, do not
re-post.

## Step 3 — Collect the result

- `GET /v3/serp/google/organic/task_get/regular/{id}` — **GoogleOrganicTaskGetRegular**
- `GET /v3/serp/google/organic/task_get/advanced/{id}` — **GoogleOrganicTaskGetAdvanced**
  (adds featured snippets and the other SERP feature elements)

Results live for **30 days** (HTML for 7). After that, collection returns `40403`
("results expired") and the task must be re-posted.

Walk the response as `tasks[] -> result[] -> items[]`. Items are polymorphic: branch on
the item `type` field (`organic`, `paid`, `featured_snippet`, `local_pack`,
`people_also_ask`, …) rather than assuming a shape.

## Step 4 — Handle the failures you will actually hit

| status_code | What to do |
|---|---|
| `40202` rate-limit per minute exceeded | You are over 2,000 calls/min. Back off. There are **no** `X-RateLimit-*` headers — this code is the only signal. |
| `40209` too many simultaneous queries | Max 30 concurrent per user. Reduce parallelism. |
| `40203` cost limit exceeded | A dashboard-configured spend cap fired. Do not retry blindly. |
| `40210` / HTTP 402 insufficient funds | Prepaid balance is empty. Stop and surface this to a human. |
| `40205` / `40206` duplicate task limit | You are re-posting the same task. Fix the caller, do not increase the limit. |
| `40102` no search results | A legitimate empty result, not an error. |
| `40103` task execution failed | Re-post with similar parameters. |
| `40505` you are using old data | Refresh your `location_code` values from the Locations endpoint. |
| `50301` 3rd party service unavailable | Upstream search engine failed. Retry later with backoff. |

Full catalog: `errors/dataforseo-problem-types.yml`. Live triage: `POST /v3/serp/errors`
(operationId **Errors**) returns the SERP tasks that errored in the past 7 days.

## Retries are billable — there is no idempotency key

DataForSEO documents **no** `Idempotency-Key`. A blind retry of `task_post` creates a
second task and charges you a second time. The safe recovery sequence after a network
failure is:

1. `POST /v3/serp/id_list` (operationId **IdList**) with a `datetime_from` /
   `datetime_to` window covering the attempt, or check `tasks_ready`.
2. Only if the id is genuinely absent, re-post.

## When to use Live instead

`POST /v3/serp/google/organic/live/regular` (**GoogleOrganicLiveRegular**) or
`live/advanced` (**GoogleOrganicLiveAdvanced**) return results synchronously in seconds.
Live requests carry **one** task per POST (2+ returns `40000`), cost more per SERP, are
not stored server-side, and time out with `50401` after 120 seconds. Use Live for
single interactive lookups; use the Standard queue for volume.

## Cost is visible inline

Every response carries a top-level `cost` (USD) and a per-task `cost`. Read it — it is the
cheapest way for an agent to stay inside a budget. Account balance and rates:
`GET /v3/appendix/user_data` (operationId **UserData**).
